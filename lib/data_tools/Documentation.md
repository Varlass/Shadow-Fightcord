# data_tools

Небольшая библиотека для преобразования данных между тремя представлениями:

- **текстовым** — простой формат для бланков, которые заполняет обычный пользователь;
- **коллекционным** — встроенные `dict`, `list`, `tuple`, `set`;
- **объектным** — экземпляры класса `Object` с доступом к данным через атрибуты.

Дополнительно модуль `operation` умеет искать и изменять значения во вложенных коллекциях.

**Требования:** Python 3.12 или новее, сторонние пакеты не нужны. Пакет не оформлен для установки через `pip`: скопируйте папку `data_tools` в свой проект.

## Быстрый старт

```python
from data_tools import text_to_collection, collection_to_text

text = """
Автор: Иван
Версия: 1.0

== Настройки ==
Язык: ru
Время: 10:30
"""

data = text_to_collection(text, dict)
# {'Автор': 'Иван', 'Версия': '1.0', 'Настройки': {'Язык': 'ru', 'Время': '10:30'}}
```

Обратите внимание: корневой тип (`dict`) передаётся аргументом, потому что в самом тексте он не хранится, а все значения из текста читаются как строки.

Термин **коллекция** в документации означает `dict`, `list`, `tuple` или `set`.

## Три представления данных

Шесть функций покрывают все направления преобразования:

| Из \ В | текст | коллекция | объект |
|---|---|---|---|
| **текст** | — | `text_to_collection` | `text_to_object` |
| **коллекция** | `collection_to_text` | — | `collection_to_object` |
| **объект** | `object_to_text` | `object_to_collection` | — |

Любая конвертация проходит одинаковые этапы: проверка аргументов → токенизация (разбор входных данных в список токенов) → проверка токенов (предупреждения) → сборка результата.

## Текстовое представление

### Назначение

Формат создан для бланков, которые заполняют обычные пользователи. Он не пугает оформлением, как JSON или YAML, и для работы с ним достаточно текстового файла (в отличие от HTML-формы).

Синтаксис подражает обычному оформлению текста: контейнер создаётся заголовком, который естественно делит текст на блоки, а уровень вложенности соответствует «размеру» заголовка — чем он длиннее, тем выше уровень.

### Правила синтаксиса

1. **Пара «ключ: значение».** Любая единица информации записывается как `ключ: значение`. Строка делится по *первому* разделителю (по умолчанию `:`), поэтому в значении двоеточие допустимо (`Время: 10:30`). Пробелы вокруг ключа и значения отбрасываются. Значение всегда читается как строка (`str`).

2. **Заголовок контейнера.** Строка, начинающаяся со спецсимвола, создаёт контейнер:

   | Символ | Тип |
   |---|---|
   | `=` | `dict` |
   | `-` | `list` |
   | `~` | `set` |
   | `%` | `tuple` |

   Принятая запись: `== Название ==`. Название — это текст без краевых спецсимволов и пробелов. Закрывающие спецсимволы необязательны и на разбор не влияют: `== Название` читается так же. Название заголовка не должно содержать разделитель `:` — иначе строка будет прочитана как пара «ключ: значение».

3. **Уровень вложенности задаёт длина заголовка.** Длина — это число одинаковых спецсимволов в начале строки; **чем длиннее, тем выше уровень**.
   - Новый заголовок закрывает все открытые заголовки, длина которых *не больше* его собственной. Контейнер, оставшийся открытым, становится родителем.
   - Поэтому вложенный контейнер должен быть *строго короче* родителя. Контейнеры одинаковой длины — соседи, даже если у них разные типы.
   - Тип спецсимвола на уровень не влияет, только количество.

4. **Принадлежность пар.** Пары до первого заголовка принадлежат корневому контейнеру. Начиная с первого заголовка каждая пара принадлежит последнему открытому заголовку. Чтобы создать новый контейнер на корневом уровне, его заголовок должен быть не короче всех открытых заголовков.

5. **Многострочные значения.** Строка без разделителя, которая не начинается со спецсимвола, считается продолжением значения предыдущей строки (строки склеиваются через `\n`, пробелы по краям каждой строки убираются).

6. **Комментарии и пустые строки.** Строки, начинающиеся с символа комментария (по умолчанию `#`), и пустые строки игнорируются — в том числе внутри многострочного значения. Пустая строка не может быть частью значения.

7. **Отступы** перед строкой не имеют значения: начальные и конечные пробелы убираются до разбора.

8. **Содержимое `list`, `tuple`, `set`.** Ключи в этих контейнерах не используются: можно писать любые (`1`, `10`) или оставить пустыми (`: Банан`), в результат попадут только значения в порядке записи. Для `set` повторяющиеся значения сливаются. По той же причине название заголовка вложенного контейнера внутри `list`, `tuple`, `set` не сохраняется.

9. **Повторяющиеся ключи в `dict`.** Побеждает последнее значение.

### Пример

```
# Комментарий игнорируется
Автор: Иван
Версия: 1.0

--- Список ---
1: Яблоко
2: Груша
: Банан

== Вложенный словарь ==
Яблок: 5
Время: 10:30
Описание: первая строка
вторая строка

%%% Кортеж %%%
1: a
2: b

~~~ Множество ~~~
x: 1
y: 1
```

Результат `text_to_collection(text, dict)`:

```python
{
    "Автор": "Иван",
    "Версия": "1.0",
    "Список": [
        "Яблоко",
        "Груша",
        "Банан",
        {
            "Яблок": "5",
            "Время": "10:30",
            "Описание": "первая строка\nвторая строка",
        },
    ],
    "Кортеж": ("a", "b"),
    "Множество": {"1"},
}
```

Как читается структура:

- `Автор` и `Версия` стоят до первого заголовка и поэтому лежат в корне.
- `--- Список ---` (длина 3) создаёт `list`. Он самый «длинный», поэтому находится в корне.
- `== Вложенный словарь ==` (длина 2) короче заголовка списка, а значит вложен в него.
- `%%% Кортеж %%%` (длина 3) закрывает оба предыдущих контейнера и становится соседом списка в корне. То же самое делает `~~~ Множество ~~~`.

### Что нельзя записать без искажений

В формате нет экранирования, поэтому такие конструкции читаются неверно:

- ключ или название заголовка с `:` (строка делится по первому двоеточию);
- строка-продолжение значения, содержащая `:` (будет прочитана как новая пара) или начинающаяся с `=`, `-`, `~`, `%` (будет прочитана как заголовок) либо с `#` (будет пропущена как комментарий);
- пустая строка внутри значения.

## Объектное представление

Функции `*_to_object` создают экземпляры класса `Object` — базового класса библиотеки.

### Как строится объект

- **Класс создаётся по имени.** Для каждого значения `class_name` создаётся свой подкласс `Object` (по умолчанию `DEFAULT_NAME`, то есть `"Object"`). Классы запоминаются в кэше `class_cache`: повторный вызов с тем же именем использует уже созданный класс. Объекты при этом каждый раз новые, а общий у них класс.
- **`dict` → атрибуты.** Ключи становятся атрибутами: `form.Имя`. Если имя нельзя записать как идентификатор (например `"11"`), используйте `getattr(form, "11")`.
- **`list`, `tuple`, `set` → `_items`.** Неименованные контейнеры хранят коллекцию в атрибуте `_items`. К самому объекту применимы индексирование (`obj[0]`), итерация, а обращения к отсутствующим атрибутам делегируются коллекции (`obj.index("b")`). Для объектов-словарей `_items` равен `None`, и индексирование не поддерживается (`TypeError`). Встроенные функции вроде `len()` к `Object` не применимы — используйте `len(obj._items)`.
- **Вложенные контейнеры** тоже становятся объектами того же класса.
- **Не используйте имена `_items` и `_add` как ключи:** они затрут служебные элементы объекта.

```python
from data_tools import text_to_object

form = text_to_object("""
Имя: Анна
Возраст: 30

== Адрес ==
Город: Омск

- Хобби -
1: чтение
2: шахматы
""", {}, class_name="Анкета")

form.Имя              # 'Анна'
form.Адрес.Город      # 'Омск'
form.Хобби[0]         # 'чтение'
form.Хобби._items     # ['чтение', 'шахматы']
```

### Добавление функций

Функции можно добавить в объект двумя способами:

1. Передать итерируемую коллекцию функций аргументом `functions` в `*_to_object`.
2. Вызвать `obj._add(function)` у готового объекта (принимает одну функцию).

Функция привязывается к экземпляру как метод под именем `function.__name__`, поэтому первым параметром она должна принимать `self`.

```python
def count(self):
    return len(self._items)

items = text_to_object("1: a\n2: b\n3: c", [], [count], "Список")
items.count()   # 3
```

### Внимание при обратной конвертации

Функции `object_to_*` обходят все атрибуты объекта (`vars(obj)`) и не знают о служебном устройстве `Object`. Поэтому в результат попадают атрибут `_items` и добавленные функции. При необходимости очищайте результат вручную.

Обычные пользовательские объекты (с атрибутом `__dict__`) тоже поддерживаются, вложенные объекты трактуются как словари.

## Предупреждения

После токенизации каждая функция проверяет токены и сообщает о подозрительных данных через стандартный модуль `warnings`. Работа при этом не прерывается.

| Класс | Когда выдаётся | Настройка |
|---|---|---|
| `EmptyKeyWarning` | ключ токена входит в `CHECKING_KEY` (по умолчанию — пустая строка) | `config.CHECKING_KEY` |
| `EmptyValueWarning` | значение токена входит в `CHECKING_VALUE` (по умолчанию набор пуст, поэтому не срабатывает) | `config.CHECKING_VALUE` |

Классы предупреждений находятся в `data_tools.conversion_internal`; оба наследуют `UserWarning`.

Что важно знать:

- В сообщении указано место: для текста — номер строки, с которой начинается запись (`line 8`), для коллекций и объектов — выражение пути (`collection["автор"]["роли"][0]`, `object.name`).
- Пустой ключ в `list`, `tuple`, `set` разрешён синтаксисом (`: Банан`), но всё равно вызывает предупреждение.
- Предупреждения можно отфильтровать стандартными средствами:

```python
import warnings
from data_tools.conversion_internal import EmptyKeyWarning

warnings.filterwarnings("ignore", category=EmptyKeyWarning)
```

- Чтобы получать предупреждения о своих значениях, добавьте их в `CHECKING_VALUE` в `config.py`, например `frozenset({"", "None"})`. Элементы должны быть хешируемыми.

## Справочник функций conversion

Во всех функциях неподходящий тип аргумента вызывает `TypeError`. Перед выполнением каждая функция проверяет аргументы.

### `text_to_collection(text, collection)`

Разбирает текст и собирает коллекцию.

| Параметр | Описание |
|---|---|
| `text: str` | текст по правилам [синтаксиса](#текстовое-представление) |
| `collection` | корневой контейнер: тип (`dict`, `list`, `tuple`, `set`) или экземпляр; определяет тип результата |

**Возвращает:** коллекцию, все скалярные значения в которой — строки.

**Особенности:**

- Переданный экземпляр изменяемой коллекции дополняется *на месте* (`update`, `extend`) и возвращается. Для `tuple` создаётся новый кортеж: исходные элементы плюс прочитанные.
- `KeyError` возникает, если первая значимая строка не содержит ключа и не является заголовком.

```python
text_to_collection("1: a\n2: b", list)      # ['a', 'b']
text_to_collection("new: 2", {"old": "1"})  # {'old': '1', 'new': '2'}
```

### `text_to_object(text, root_type, functions=None, class_name=DEFAULT_NAME)`

Разбирает текст и собирает объект `Object`.

| Параметр | Описание |
|---|---|
| `text: str` | текст по правилам синтаксиса |
| `root_type` | корневой контейнер (экземпляр или тип): `dict` даёт объект с атрибутами, остальные типы — объект с `_items` |
| `functions` | итерируемая коллекция функций для добавления в объект или `None` |
| `class_name: str` | имя создаваемого класса |

**Возвращает:** `Object` (значения — строки). См. [Объектное представление](#объектное-представление).

### `collection_to_text(collection)`

Преобразует коллекцию в текст.

| Параметр | Описание |
|---|---|
| `collection` | `dict`, `list`, `tuple` или `set` |

**Возвращает:** строку по правилам синтаксиса.

**Особенности:**

- Тип корневой коллекции в тексте не записывается — при обратном чтении его нужно указать.
- Значения записываются как `str(значение)`: `5` → `5`, `None` → `None`. Типы при обратном чтении не восстанавливаются.
- Ключи `list`, `tuple`, `set` — номера элементов, начиная с 1. Названия заголовков вложенных контейнеров внутри них — тоже номера.
- Длина заголовка зависит от глубины: у самого глубокого контейнера — один символ, и на каждый уровень выше на символ больше.
- Пары «ключ: значение» всегда выводятся раньше вложенных контейнеров, а элементы одного контейнера — в **обратном порядке**.

```python
data = {
    "название": "Отчёт",
    "число": 5,
    "автор": {"имя": "Иван", "роли": ["редактор", "рецензент"]},
    "размер": (1, 2),
}
print(collection_to_text(data))
```

```
число: 5
название: Отчёт
== автор ==
имя: Иван
- роли -
2: рецензент
1: редактор
%% размер %%
2: 2
1: 1
```

### `collection_to_object(collection, functions=None, class_name=DEFAULT_NAME)`

Преобразует коллекцию в объект `Object`.

| Параметр | Описание |
|---|---|
| `collection` | `dict`, `list`, `tuple` или `set` |
| `functions` | итерируемая коллекция функций или `None` |
| `class_name: str` | имя создаваемого класса |

**Возвращает:** `Object`. Типы значений сохраняются (в отличие от текста, где всё превращается в строки).

### `object_to_text(obj)`

Преобразует объект в текст.

| Параметр | Описание |
|---|---|
| `obj` | объект с атрибутом `__dict__` (экземпляр обычного класса, в том числе `Object`) |

**Возвращает:** строку по правилам синтаксиса. Атрибуты со значениями-коллекциями становятся заголовками, вложенные объекты записываются как `dict`. Особенности вывода те же, что у `collection_to_text`.

```python
class Point:
    def __init__(self):
        self.x = 1
        self.y = 2

print(object_to_text(Point()))
```

```
y: 2
x: 1
```

### `object_to_collection(obj, collection=None)`

Преобразует объект в коллекцию.

| Параметр | Описание |
|---|---|
| `obj` | объект с атрибутом `__dict__` |
| `collection` | тип или экземпляр коллекции; по умолчанию `dict` |

**Возвращает:** коллекцию. Для `dict` имена атрибутов становятся ключами, для `list`, `tuple`, `set` сохраняются только значения. Типы значений не изменяются. Переданный экземпляр изменяемой коллекции дополняется на месте.

```python
object_to_collection(Point())        # {'x': 1, 'y': 2}
object_to_collection(Point(), list)  # [1, 2]
```

## Модуль operation

> Модуль находится в разработке. Описание соответствует текущему поведению и может измениться.

### `Node`

Описание найденного узла (`dataclass`):

| Поле | Описание |
|---|---|
| `path: tuple` | ключи и индексы от корня до узла (сам корень узлом не считается) |
| `parent` | контейнер, в котором лежит значение |
| `key` | ключ или индекс значения в `parent` |
| `value` | само значение |

### `fetch(container, *, target_path=MISSING, target_value=MISSING) -> list[Node]`

Находит все узлы в `dict` и `list`, обходя вложенные контейнеры сверху вниз (родитель всегда раньше потомков).

| Параметр | Описание |
|---|---|
| `container` | `dict` или `list` |
| `target_path` | строка с ключами через точку |
| `target_value` | искомое значение, сравнивается через `==` |

Как работает сопоставление:

- **Путь** совпадает, если указанные ключи образуют *конец* пути узла. `"имя"` найдёт ключ `имя` на любой глубине, `"сервер.имя"` — только `имя` внутри `сервер`.
- **Значение** сравнивается оператором `==` (поэтому `1`, `1.0` и `True` считаются равными).
- Если заданы оба критерия, узел подходит при выполнении **любого** из них. Если не задан ни один, возвращается пустой список.

```python
cfg = {"сервер": {"имя": "main", "порты": [80, 443]}, "имя": "корень"}

[n.path for n in fetch(cfg, target_path="имя")]
# [('сервер', 'имя'), ('имя',)]

[n.path for n in fetch(cfg, target_path="сервер.имя")]
# [('сервер', 'имя')]

[n.path for n in fetch(cfg, target_value=443)]
# [('сервер', 'порты', 1)]
```

### `edit(container, change, *, target_path=MISSING, target_value=MISSING)`

Заменяет значения всех найденных узлов. Критерии поиска те же, что у `fetch`. Контейнер изменяется на месте, функция ничего не возвращает.

| Параметр | Описание |
|---|---|
| `change` | новое значение **или** функция: она получает старое значение и возвращает новое |

```python
edit(cfg, str.upper, target_path="сервер.имя")  # имя → 'MAIN'
edit(cfg, 8080, target_value=80)                # порты → [8080, 443]
```

### Текущие ограничения

- Обходятся только `dict` и `list`. Внутрь `tuple`, `set` и `Object` поиск не заходит, и `edit` по ним ничего не меняет.
- Элементы пути сопоставляются как строки, поэтому индекс списка (число) через `target_path` найти нельзя. Используйте `target_value`.
- Если `change` — функция, она всегда вызывается; сохранить саму функцию как значение через `edit` нельзя.
- Если один и тот же `edit` заменяет и контейнер, и значение внутри него, правка вложенного значения теряется.

## Настройка (config.py)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SYNTAX["types"]` | `=` → `dict`, `-` → `list`, `~` → `set`, `%` → `tuple` | спецсимволы заголовков |
| `SYNTAX["commentary"]` | `#` | символ комментария |
| `SYNTAX["separator"]` | `:` | разделитель ключа и значения |
| `DEFAULT_NAME` | `"Object"` | имя класса по умолчанию для `*_to_object` |
| `CHECKING_KEY` | `frozenset({""})` | ключи, вызывающие `EmptyKeyWarning` |
| `CHECKING_VALUE` | `frozenset()` | значения, вызывающие `EmptyValueWarning` |

Правила:

- Спецсимволы — одиночные символы.
- Символ комментария, разделитель и маркеры типов должны быть разными символами, иначе разбор станет неоднозначным.
- Настройки читаются при импорте пакета, поэтому редактируйте сам файл `config.py`, а не переприсваивайте переменные во время работы программы.
- Элементы `CHECKING_KEY` и `CHECKING_VALUE` должны быть хешируемыми.

## Особенности и ограничения

- **Типы значений.** Из текста значения всегда читаются как `str`, а при записи в текст приводятся через `str()`. Числа, `None` и `bool` после цикла «в текст и обратно» становятся строками; ключи — тоже.
- **Корневой тип.** В тексте он не записывается, его всегда указывают при чтении.
- **Порядок элементов.** При записи в текст (`collection_to_text`, `object_to_text`) пары «ключ: значение» идут перед вложенными контейнерами, а элементы одного контейнера — в обратном порядке. Если порядок важен (например, для `list` и `tuple`), учитывайте это при цикле «в текст и обратно».
- **Экранирование отсутствует.** См. [Что нельзя записать без искажений](#что-нельзя-записать-без-искажений).
- **Поддерживаемые типы.** Только `dict`, `list`, `tuple`, `set`. Подклассы (`OrderedDict`, `namedtuple` и т. п.) не гарантируются.
- **Глубина и циклы.** Обход рекурсивный: очень глубокая вложенность (порядка тысячи уровней) и циклические ссылки приведут к `RecursionError`.
- **Размер данных.** Время обработки растёт быстрее, чем число элементов, поэтому библиотека рассчитана на документы небольшого и среднего размера (до нескольких тысяч элементов).
